# 司令席（Cockpit）

自分のClaudeセッションを横断して、**状態別**に一枚の板へ並べる Claude Code スキル。

## はじめに読む（3分）

**何をするものか。** Claude Code のセッションで `/cockpit` と打つと、自分が開いてきた
セッションを集めて、状態ごとに4列の板を作る。左から「あなた待ち」「稼働中」
「レビュー待ち」「停止・環境消失」。板はWebページ（Artifact）として作られ、
2回目以降は**同じURLが上書きされる**ので、タブに置いておける。

**何が解決するか。** Claudeを何台の端末から開いても、ローカルの履歴は端末ごとに閉じていて
横断できない。結果、「あれ、あの件はどこで止まっていたか」が分からなくなる。この板の
一番左の列が、**自分の返事がないと進まないセッション**を、待たせている順に並べる。

**何が見えて、何が見えないか。**

- 見える: 自分がクラウド（claude.ai/code、デスクトップアプリ、スマホ）で開いたCodeセッション
- **見えない: 他人のセッション**。板は一人に一枚で、混ざらない
- 見えない: claude.ai の**通常のチャット**（Code以外）。下の「まだ無いもの」
- 見えない: ターミナルのローカルCLIだけで動かしたセッション

**扱いの注意。** 板には案件名や「何を待っているか」が並ぶ。既定で非公開のまま使い、
**共有しない**。下の「機密」。

## 入れ方

スキルは**1ディレクトリで完結している**（`SKILL.md` と `build_cockpit.py`）。
Python 3 標準ライブラリのみ。依存なし。

**A. このリポジトリを開いたセッション** — 導入不要でそのまま使える。

**B. どのセッションでも使いたい** — その端末の個人スキル置き場に**ディレクトリごと**コピーする:

```bash
mkdir -p ~/.claude/skills
cp -R .claude/skills/cockpit ~/.claude/skills/
```

`SKILL.md` だけでは動かない（`build_cockpit.py` を同じディレクトリから呼ぶ）。
これは端末ごとの作業（`~/.claude/` は同期しない）。4台あれば4回。
リポジトリを持っていない人は、この2ファイルを受け取って同じ場所に置けば同じように動く。

## `/cockpit` は何をするか

画面へ「飛ぶ」コマンドではない。**集計してArtifactを上書きし、待ちの一覧とURLを返す**。
画面を見るのはそのURLを開く操作（ターミナルなら `/artifacts`、直前のものは ctrl+］）。

板は**その人の初回に作られ、以後は同じURLが上書きされる**。手順書に個人のURLは書かない。
`Artifact` の `action: "list"` でタイトルに「司令席」を含むものを探し、あれば上書き、
無ければ新規に作る。他人のArtifactには publish できないため、この形にしてある。

手で回す場合:

```bash
python3 build_cockpit.py sessions.example.json -o out/cockpit.html
```

## なぜこの形か

作りたかったのは、X上で見た「Claude / Codex コックピット」（列＝アカウント／ウィンドウ、
ローカルの `~/.claude/projects/**` の JSONL を監視する形）だった。調べたうえで設計を変えた。

| 元ネタの前提 | こちらの実態 |
|---|---|
| Claude + Codex の2系統 | Codexは使っていない |
| 複数課金アカウントを同時ログイン | 他人のアカウントは束ねない（機密・規約） |
| 列＝アカウント／ウィンドウ | 列＝**状態**。ボトルネックは稼働状況ではなく「自分の返事待ち」 |
| ローカルJSONLを端末で監視 | 端末が複数あり横断不可。クラウドのセッションAPIはアカウント単位で最初から横断 |

`list_sessions` は `status_bucket`（作業中／入力待ち／レビュー待ち）と
`post_turn_summary.needs_action`（**何を待っているかの文章**）を返す。
元ネタのカンバンには無い情報で、ここがこの画面の中身になっている。

## データ契約

`build_cockpit.py` は次の形の JSON を読む。1件あたり `id` 以外はすべて省略可。

| キー | 意味 |
|---|---|
| `id` | `session_...`。カードのリンク先（`https://claude.ai/code/<id>`）になる |
| `title` | セッション名 |
| `bucket` | `SESSION_STATUS_BUCKET_BLOCKED` / `_WORKING` / `_REVIEW_READY`（短縮形 `blocked` 等も可） |
| `origin` | `desktop_app` / `web_claude_ai` / `android` / `claude_code_cli` |
| `kind` | `anthropic_cloud` / `bridge`（`bridge` は端末常駐。バッジが付く） |
| `repo` / `branch` | `owner/repo` と作業ブランチ |
| `model` / `cost_usd` | 表示のみ |
| `updated_at` | RFC3339。**経過日数の基準** |
| `status_detail` | 直近の報告。`needs_action` が無いときカードに出る |
| `needs_action` | 何を待っているか。あればこれを優先して出す |
| `unread` / `error` | バッジ。`error` は `environment_deleted` 等 |

トップレベルに `generated_at`（RFC3339）を入れると、経過日数と時刻表示の基準になる。
無ければ実行時刻。`sessions.example.json` が最小の例。

## 画面の決めごと

- **列は状態**、左から あなた待ち → 稼働中 → レビュー待ち → 停止・環境消失
- **「あなた待ち」は古い順**。待たせている順に上から並ぶ
- **環境が消えたセッションは、入力待ちでも「停止」に置く**。答えても届かないため、
  待ち行列に混ぜると数字が嘘になる
- 数字は最終更新からの経過日数（`tabular-nums`）
- 絞り込みは「あなた待ちだけ」とリポジトリ。JSは50行程度、外部依存なし
- **セッションIDをカードに出す**（選択してコピーできる）。リンクで開けなかったときや、
  環境が消えて新セッションを立てるときに、これで元を探せる
- **タイトルのリンクに `target="_blank"` を付けない。** Artifactは砂箱の中で動き、外部リンクの
  クリックは親フレームへ転送される。`target` を付けると必ず新規ウィンドウになり、空白のまま
  出ないことがあった（2026-09-02 利用者報告）。付けなければ開き方は閲覧側に任される

## 機密

- 集計した実データと出力HTMLは**コミットしない**（`.gitignore` 済み）
- `needs_action` には取引先担当者の氏名が入ることがある。正規化の段で属性へ言い換える
- Artifactは既定で非公開。**共有しない**。板は一人に一枚あるもので、見せ合うものではない

## まだ無いもの

- **送信**（この画面から指示を流す）。**2026-09-02に検証して不可と分かった**——クラウドの
  セッションからは `ListAgents` が "No reachable agents" を返し、`send_message` 相当も渡されない。
  届くのは同じ端末上のセッション同士だけ。送れる司令席はローカルに置くしかなく、その代わり
  横断を失う（元ネタが端末ごとの設計だった理由がこれ）
- **ローカルCLIセッションの横断**。各端末から索引JSONを1箇所へ吐かせる層が必要
- **claude.ai の通常会話**。`list_sessions` はCodeセッションのみ。通常のチャットを一覧する
  ツールは（2026-09-02時点で）渡されておらず、会話ページ自体も外から読めない（403）。
  加えて、通常会話には `status_bucket` や `needs_action` に相当する構造が無く、
  「何を待っているか」がデータとして取れない——仮に一覧できても板の列に振り分けられない。

  **運用でこれを回避する。** 板に載せたい案件は、成果物がプログラムでなくても
  **Code側でスレッドを開く**（2026-09-02 決定）。通常会話は使い捨ての調べものに留める。
